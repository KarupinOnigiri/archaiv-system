{# Renders ONE checkout instance (a dialog + its minimized dock). Staff can have several of these in flight at once -- e.g. one minimized while a second trainee is being checked out -- so this partial is designed to be rendered once per session and concatenated/appended into the page, rather than replacing whatever's already there. Every instance is identified by `client_id`, which the caller must always provide: - Starting a brand-new checkout (no session yet): the "New Checkout" button mints a throwaway crypto.randomUUID() client-side and sends it as ?client_id=... to /start-form. There's no real session id yet, so this is the only id available to scope the DOM to. - Resuming or restoring an existing session (/resume-form, /dock): client_id is just the session's own id. That's what lets the JS recognize "this session is already open in this tab" (see Checkout.resumeOrExpand in base.html) without a separate lookup. `auto_minimize` is only ever true for the page-load /dock restore -- the dialog renders closed and stays in its dock. `resume_session` is passed for both /resume-form and /dock; it's absent for a fresh /start-form render. #}
